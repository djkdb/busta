# AI Workflow

> 이 문서는 **실제로 사용한 AI와 역할만** 기록합니다. 사용하지 않은 도구를 쓴 것처럼 적지 않습니다.
> 개발자가 이 Repository 밖에서 사용한 AI(예: 아이디어 구상에 쓴 챗봇)는 `✍️ 직접 기입` 칸에 추가해 주세요.

## 사용한 AI 도구

| 도구 | 역할 | 사용 단계 |
|---|---|---|
| **Claude Code** (클라우드 세션, Anthropic) | 기술 리드/페어 프로그래머: Repository 분석, 아키텍처 설계, 구현, 테스트 작성, 브라우저 검증, 문서화 | 설계 → 구현 → 테스트 → 디버깅 → 문서 |
| Claude Code **서브에이전트** (general-purpose) | 데이터 소스 조사 전담 — 메인 작업과 **병렬**로 WebSearch/WebFetch 조사 후 보고서 작성 | 데이터 조사 |
| Playwright + Chromium (AI가 조작) | AI가 직접 브라우저로 사용자 플로우를 클릭하고 스크린샷을 보고 UI 결함을 찾음 | 검증 |
| ✍️ 직접 기입 | (예: 문제 아이디어 구상에 사용한 도구) | 문제 정의 |

## 개발 파이프라인에서의 AI 역할

```
문제 정의 ──── 사람: 실제 겪은 불편 (금요일 청주→서울 도착시간)
   ↓
요구사항 정리 ── 사람: 마스터 프롬프트 작성 (제품 철학·금지 방향·심사 기준 포함)
   ↓
Repository 분석 ─ AI: 빈 저장소 확인 → 스택 결정 (Next.js 16 + TS + Tailwind + Vitest)
   ↓
Architecture ─── AI 제안: Provider/Engine 분리, direction 필드, factors, isRealData
   ↓                사람이 정한 원칙("Mock은 Mock이라고 쓴다")을 타입으로 강제
데이터 조사 ──── AI 서브에이전트(병렬): 14개 소스 조사, 신뢰도 3등급 표기
   ↓
구현 ────────── AI: 도메인 → 시간 유틸 → Provider → Engine → UI 순으로 작은 커밋
   ↓
테스트 ───────── AI: 날짜/시간 경계(자정, 윤년, 월말), 잘못된 입력, 방향별 패턴
   ↓                + 4개 타임존에서 테스트 재실행
브라우저 검증 ── AI: Playwright로 실제 클릭 → 스크린샷 판독 → 결함 3건 발견 → 수정
   ↓
문서화 ───────── AI 초안 + 사람 검토 (특히 data-sources의 "미확인" 항목)
```

## AI와 협업하면서 정한 규칙

1. **AI에게 "숫자를 만들지 말라"를 명시한다.** 마스터 프롬프트에 "정확도 92% 같은 수치를 임의로 만들지 않는다"를 넣었고, 그 결과 AI가 신뢰구간·확률 표시를 스스로 배제했다.
2. **AI의 조사 결과는 신뢰도 등급과 함께 받는다.** 서브에이전트 프롬프트에 "확인 못 하면 '미확인'으로 표시"를 넣었다. 실제로 공식 사이트가 차단되었을 때 AI가 추측으로 채우지 않고 등급을 나눠 보고했다.
3. **"테스트 통과 = 완료"로 보지 않는다.** 유닛 테스트 47개가 통과한 뒤에도 브라우저 스크린샷에서 ETA와 차트 숫자 불일치를 발견했다 (`troubleshooting.md` #3).
4. **작은 단위로 커밋한다.** Git 히스토리 자체가 개발 과정 설명이 되도록 기능 단위 메시지를 쓴다.
5. **AI가 우회책을 쓰지 않게 한다.** npm 의존성 충돌을 `--legacy-peer-deps`로 덮지 않고 원인(`@types/node` 버전)을 고쳤다.

## 환경 설정

| 항목 | 설정 |
|---|---|
| 런타임 | Node 22 (`.nvmrc`), npm |
| 프레임워크 | Next.js 16 App Router, React 19, TypeScript strict |
| 스타일 | Tailwind CSS v4, CSS 변수 토큰 (라이트/다크) |
| 테스트 | Vitest 5 (`npm test`) |
| 품질 | ESLint (`npm run lint`), `npm run typecheck` (Next typegen + tsc) |
| AI 가이드 파일 | `AGENTS.md` / `CLAUDE.md` — Next.js 16이 생성한 "학습 데이터와 다른 버전이니 번들 문서를 먼저 읽어라" 규칙. 실제로 AI가 `node_modules/next/dist/docs`에서 `searchParams`가 Promise인지 확인한 뒤 구현함 |

## 중간 발표용 요약 (AI 활용 계획 40%)

- **도구 선정 이유**: 코드·터미널·브라우저를 모두 다룰 수 있는 에이전트형 AI(Claude Code)를 택해, "코드 생성"이 아니라 "설계–구현–검증–기록" 전 과정에 투입
- **병렬화**: 데이터 조사처럼 독립적인 작업은 서브에이전트에 맡기고 메인은 구현을 진행
- **검증 루프**: AI가 만든 결과를 AI가 다시 검증 (다중 타임존 테스트, 브라우저 스크린샷 판독)
- **사람의 역할**: 문제 정의, 제품 철학(정직성), 조사 결과 검토, 우선순위 결정
