# 로드맵

## 1. Mock MVP · 이번 작업

검색 → 엔진 → 소요시간/도착시간 → 시간대 비교의 작동 흐름, 입력 검증, 모바일 레이아웃, 개발 기록과 테스트를 만든다. 완료 여부는 validation.md의 실제 실행 결과로 확인한다.

## 2. 문제 검증 / 중간 발표 준비

실제 버스 이용자에게 출발시간 비교가 어떤 일정 결정에 도움이 되는지 확인한다. 5–7분 발표는 문제(1분), MVP(2분), AI 워크플로우·프롬프트와 검증(2분), 데이터 확보 계획(1분)으로 구성한다. 발표 날짜는 사용자 안내의 11월 초 예정이며 별도 확인이 필요하다.

## 3. Historical Data

확보 가능한 운행 데이터·이용 조건 조사 → 실제 터미널/방향/경유 기준으로 노선 정의 → 실제 출발·도착 기록의 품질 검증 → 요일/시간대 평균과 표본 수 표시 → 보지 않은 기간으로 평가. 사용자의 제보를 수집한다면 개인정보 최소화와 데이터 검증부터 설계한다.

## 4. Traffic Data

공식 제공자 문서에서 사용 가능한 API를 조사한다. 시외버스 경로와 도로 교통의 연결 가능성을 검증하고, 실제 응답·오류·쿼터에 대한 계약을 작성한다. 제공자 구현과 서버 API 경계를 추가한다. 자동차 ETA를 버스 실측 ETA로 표현하지 않는다.

## 5. Prediction Model / 최종 발표

충분한 표본이 모이면 시간 기준 train/validation/test 분리를 사용해 누수를 방지한다. 단순 시간표와 과거 평균을 기준선으로 삼아 MAE 등 오차를 비교한다. 개선 여부가 확인될 때만 복잡한 모델을 채택한다. 목표 도착시간 검색은 데이터 범위와 불확실성 표기가 마련된 후 추가한다.

최종 7–10분 발표는 시연, 프롬프트 개선, 실제 실패와 수정, 배운 점 중심으로 구성한다. 예정은 12월 말이며 이번 단계에서는 정확도 수치를 만들지 않는다.
