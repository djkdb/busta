# 예측 검증 기록 (Validation)

> BUSTA는 "정확도"를 **실제 운행 기록과 비교해 측정한 뒤에만** 말한다. 이 문서는 그 측정 기록이다.
> 표본이 작을 때는 결론을 일반화하지 않는다.

## #1 — 2026-09-26(토, 추석 연휴) 청주(고속) ↔ 서울경부, 가정 규칙(Mock) vs 실제

### 데이터
- 실제: 공공데이터포털 TAGO 고속버스도착정보, 17:19·17:20 KST 조회 (`tests/fixtures/data-go-kr/arrival-*.json`)
- "도착완료" 상태 8편의 출발시각 → 도착 기록 시각
- 시간표: TAGO 고속버스정보 (두 방향 모두 90분)
- BUSTA: 당시의 `MockTravelTimeDataProvider` (가정 규칙)

### 해석
- 이날 오후에는 **시간표가 BUSTA보다 훨씬 정확했다.** BUSTA는 모든 편을 과대 예측했다.
- 원인: 9/26은 공휴일(추석 연휴)이라 "일요일·공휴일 귀가 정체(수도권 방향 +28%)" + "주말·공휴일 오후 정체(+10%)" 규칙이 적용됐다. 하지만 추석 **다음날 토요일 오후**에는 서울 방향 정체가 없었다. "공휴일이면 귀경 정체"라는 가정이 너무 단순했다.
- 한계: **하루, 한 노선, 오후 1시간 반, 8편**이다. 이것만으로 규칙을 고치면 이 하루에 과적합된다.

### 결정
1. 가정 규칙 수치는 **지금 고치지 않는다.** 대신 결과 화면에 "오늘 이 노선 실제 운행"(🟢 실제 데이터)을 BUSTA 예측 옆에 보여줘서, 사용자가 가정 규칙과 실제를 직접 비교할 수 있게 했다.
2. 실제 도착 기록을 **계속 수집**해 요일·시간대·공휴일 유형별 표본이 쌓이면, 그때 규칙을 실측 비율로 교체한다 (Historical 엔진, roadmap Phase 4).
3. 발표에서 "정확도 몇 %"를 말하지 않는다. 대신 이 표를 보여준다: **"가정만으로 만든 예측은 틀렸고, 그래서 실제 데이터를 쌓는 구조로 바꿨다."**
